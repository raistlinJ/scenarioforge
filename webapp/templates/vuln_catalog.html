Sync CORE runtime with this catalog?

        
      

      

        

          This compares the vulnerability catalogs on the CORE VM against the ones installed here and
          deletes every remote catalog that is not installed on this machine.
        

        

          Items marked Persistent are removed too if their catalog is not installed
          here. Persistent protects an item from image cleanup within a catalog; it does not
          protect a copy of a catalog this machine no longer has.
        

        

          Deleting a catalog only removes it locally, so run this afterwards — or after pointing
          the deployment at a different CORE VM, which still holds whatever the previous deployment
          installed. Use Preview first to see what would be removed.
        

        

      

      

        
        
        
      

    

  







  

    

      

        
Validate image architectures?

        
      

      

        

          Validation resolves the CPU architectures of every image in the catalog. Images this
          host has already pulled are read locally; anything else costs a
          docker manifest inspect call to the registry (Docker Hub for most
          catalogs).
        

        

          It downloads manifests only, never image layers — but for a large catalog it is
          the slowest part of an import, and it counts against registry rate limits.
        

        

          Skipping leaves each item's architecture unscanned. On an arm64 CORE VM that
          is the check which warns you before an amd64-only stack runs under emulation.
